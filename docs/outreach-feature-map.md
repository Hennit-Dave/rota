# Outreach feature map

Which Rota feature to lead with for which kind of company. Updated when a feature is finished
(`.agents/rules/evidence-capture.md`); outreach points at the feature closest to the company's product.

Rows start as **planned**. A row becomes **ready** only when its evidence exists and is linked.

| Feature | Kind of company | Evidence to show | Status |
|---|---|---|---|
| Shift swap requests with manager approval: exchange two shifts atomically, idempotent against retried taps, optimistic update with rollback, offline never queued | Shift-scheduling and workforce tools | ADR 0023; five simultaneous retries give one request (test); Staff approving gets 403 and nothing changes (test); [PR #50](https://github.com/Hennit-Dave/rota/pull/50): emulator screenshots of the request, the failure and the approval | built (PR #50) |
| Seat-based billing with server-side proration and an append-only ledger | B2B SaaS with per-seat pricing | ADR 0026; the proration engine's 35 unit cases (the brief's example is 2000); a ledger the database refuses to `UPDATE`, `DELETE` or `TRUNCATE`; state rebuilt from the ledger matches the stored state on both shards (tests). Activation (P3, ADR 0027): Stripe Checkout in test mode, a signature-verified webhook recorded once by event ID and decided in a background job that matches amount, currency, team and session, and server-side seat limits (the sixth Starter seat is refused) | activation and plan or seat changes built (test mode): a quote the engine makes, a version-checked, engine-re-derived apply, and a ledger-backed billing history; reductions at period end (the Owner chooses who becomes inactive; a job re-checks at the boundary) built; applying them and renewals next |
| Quiet-hours-aware, time-zone-aware notifications | Anything with on-call or shift staff (healthcare, hospitality, retail) | PR, clip of a delayed notification | planned |
| Cursor-paginated activity feed at 10,000+ records, load tested at 200 users | Any product with large feeds or timelines | [PR #49](https://github.com/Hennit-Dave/rota/pull/49): `EXPLAIN ANALYZE` before/after (5.5 ms seq scan + sort to 0.056 ms index scan on 10,000 rows), stable paging under new activity (tests), 66 rows paged in 4 requests across ~30 fast flings; load test report still to come | built (PR #49; load test pending) |
| Per-user settings the server owns and every device follows: a server-set `updatedAt` per setting (most recent wins, weakness documented), one-field requests so two devices' changes to different settings both survive, optimistic update with rollback per field, offline changes never queued, a per-user theme | Mobile B2B and consumer apps with preferences across devices, and any workforce or on-call tool | ADR 0024; a theme change and a quiet-hours change from two devices both kept (test); a failed change rolls back only its own field (test); PR (link when opened) | built (PR pending) |
| Offline viewing with cross-device settings sync | Mobile-first workforce and field-service tools | PR, offline clip | planned |
| Role-based permissions and team isolation, proven by tests | HR and multi-tenant B2B SaaS | [PR #34](https://github.com/Hennit-Dave/rota/pull/34): isolation across two shards (404), role enforcement (403), demotion with the same token | built (PR #34) |
| Email invitations that send exactly once: single-use hashed tokens, a durable background job with idempotency keys, queue-loss recovery | B2B SaaS with team onboarding, and any product that sends transactional email | [PR #36](https://github.com/Hennit-Dave/rota/pull/36) (server half): a lost invite email on shard B restored by the sweep, one real Resend send, mutation-checked security tests | built (PR #36, server half) |
| Shareable single-use invite links: a bearer credential made safe by bounds (Staff only, once, a short life, revocable, capped per team), race-proof (five simultaneous acceptances give one membership), shown once with only its hash stored | B2B SaaS with team onboarding, and workforce, hospitality and retail tools where staff join from a group-chat link | ADR 0025; the single-use race and the identical answer for every unusable link (tests); PR (link when opened) | built (PR pending) |
| Deep-link invitations that survive sign-in and sign-up and land the invitee in the right team, with invite and management screens driven by the server's permission answers | Mobile B2B SaaS with team onboarding, and workforce, hospitality and healthcare tools | [PR #40](https://github.com/Hennit-Dave/rota/pull/40) (app half): clips of six device bugs, each recorded broken then fixed; an invitee accepted into a team on the other shard; a Manager shown an Owner's invitation with no buttons | built (PR #40, app half) |
| A shift calendar that is correct in the team's own time zone (across daylight saving), refuses double-booking under concurrency, and writes its own audit trail in the same transaction | Shift-scheduling, hospitality, healthcare and retail workforce tools | [PR #47](https://github.com/Hennit-Dave/rota/pull/47): ADR 0021; five simultaneous bookings of one person give exactly one (test); week windows across a clock change (unit tests); emulator screenshots | built (PR #47) |
